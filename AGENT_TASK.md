# TASK: Backend Code Review и Улучшение

## 1. Контекст

Проект: backend-сервис на FastAPI.
Цель: провести аудит и улучшить backend-код без затрагивания фронтенда.

## 2. Область анализа

Анализировать ТОЛЬКО backend.

Исключить полностью:

* frontend-код
* любые файлы с Bootstrap
* HTML / CSS / JS (если это не критично для backend)

Разрешено:

* читать и изменять `.env` файлы (при необходимости для улучшения структуры конфигурации)

## 3. Цели ревью

### 3.1 Архитектура

* Проверить разделение слоёв (router / service / repository)
* Устранить утечки логики между слоями
* Привести структуру к консистентной

### 3.2 Качество кода

* Удалить дублирование
* Усилить типизацию
* Проверить соответствие SOLID
* Улучшить нейминг

### 3.3 Ошибки

* Привести обработку исключений к единому виду
* Убедиться в корректных HTTP-статусах
* Исключить "голые" Exception

### 3.4 Безопасность

* Проверить работу с JWT
* Проверить валидацию входных данных
* Проверить использование переменных окружения
* Убедиться, что секреты не логируются и не утекают

### 3.5 Производительность

* Проверить запросы к БД
* Устранить блокирующие операции
* Упростить зависимости

### 3.6 Тесты

* Добавить unit-тесты для сервисов
* Добавить тесты для ключевых API-эндпоинтов
* Использовать pytest
* Покрыть критические сценарии (auth, ошибки, edge cases)

### 3.7 Документирование кода

* Добавить комментарии в коде, поясняющие:

  * назначение функций и классов
  * нетривиальную бизнес-логику
  * сложные участки кода
* Не писать избыточные комментарии (избегать очевидного)

## 4. Ограничения

Запрещено:

* Трогать frontend (включая Bootstrap)
* Выполнять любые git-операции (commit, push, pull, merge, rebase и т.д.)
* Менять бизнес-логику без объяснения
* Ломать API-контракты
* Вносить массовые переписывания

Разрешено:

* Рефакторинг backend-кода
* Улучшение структуры
* Изменение `.env` файлов (если это улучшает конфигурацию)
* Добавление тестов
* Добавление комментариев в код

## 5. Формат результата

### 5.1 Критические проблемы

Риски, баги, уязвимости

### 5.2 Существенные улучшения

Архитектура, читаемость, стабильность

### 5.3 Минорные замечания

Стиль, нейминг

### 5.4 Конкретные изменения

Для каждого изменения:

* было
* стало
* причина

### 5.5 Тесты

* какие тесты добавлены
* что покрывают
* как запускать

## 6. Отчёт о работе (обязательно)

Создать файл:
`AGENT_REPORT.md`

В файле указать:

* список всех изменений
* какие файлы изменены
* какие файлы созданы
* краткое объяснение по каждому изменению
* потенциальные риски

## 7. Дополнительно

* Предложить улучшенную структуру проекта
* Указать анти-паттерны
* Дать рекомендации по best practices

* Действовать как senior backend engineer
* Делать точечные изменения
* Объяснять каждое изменение
* Не переписывать проект целиком
